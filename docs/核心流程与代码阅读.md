# 核心流程与代码阅读

先读页面 XML，再读同名 Java，最后追踪 Repo 和 Store。所有类都放在同一包中，便于初学者打开定位；没有引入 MVVM、协程或依赖注入。

## 公共页面

BaseActivity.setScreen 加载页面 XML，绑定 view_toolbar 的标题和返回按钮，处理系统边距。各页面使用 include 复用身份信息，但内容不是由一个巨大公共方法动态生成。

首页点击按钮时通过显式 Intent 启动对应 Activity；需要参数时创建 Bundle，使用 putExtras。R.id 的判断使用 if/else，避免新版 AGP 非 final 资源 ID 无法用于 switch 的问题。

## 阅读与收藏

ChapterListActivity 获取 JSON 章节，用 SimpleAdapter 展示。点击章节发送 chapter_id。KnowledgeActivity 读取本章目录，输入关键词时用 TextWatcher 搜索全部知识的标题、正文、属性、示例和提醒。KnowledgeAdapter 展示标题、所属章、掌握状态及收藏状态。

点击知识发送 knowledge_id，KnowledgeDetailActivity 绑定标题、概念、属性、代码和提醒。首次进入将状态从 0 改为 1；勾选后改为 2。首次设置 CheckBox 时用 binding 标志，避免程序切换知识时监听器错误写入。星形 ImageButton 修改 favorite 表。

学习位置 last 放入 SharedPreferences。返回首页或知识列表时 onResume 重新查询，反映最新状态。

## 答题

QuizActivity 用 XML 声明四个 RadioButton 和四个 CheckBox，一次显示一道题，前后切换时替换题目文字。答案保存在 ArrayList<TreeSet<Integer>>，每题一个集合。单选先清空后加入，多选按勾选状态加入/移除。

渲染题目时 binding=true，避免程序恢复选项触发监听器后清除旧答案。切题不丢选择；onSaveInstanceState 保存当前题号、章节、答案集合和本次 token，系统重建时恢复。未提交草稿不永久写入数据库。

Grading.encode 对集合排序去重，生成如 0,2 的字符串；标准答案与用户答案完全一致才算正确。少选、多选、未答均错。完整章节每题 10 分；错题重练按 1/1 题结果显示。

提交前 AlertDialog 提示未答数量；submitting 标志和数据库唯一 token 阻止同次重复提交。Store.submit 使用 SQLite 事务一次保存 attempt、answer 和 wrong。成功后传 attempt_id 给结果页并 finish 答题页。

## 存储与兼容性

Repo 读取三个 assets JSON，并检查重复 ID、章节归属、答案范围和解析缺失。它不保存用户行为。

Store 继承 SQLiteOpenHelper，沿用 finstudy.db 版本 1：progress、favorite、attempt、answer、wrong 五张表。没有改变旧表结构。创建表只发生在新数据库，升级覆盖安装不清空旧表。onUpgrade 仍没有迁移，因为本次不改变版本；今后若改结构需正式实现迁移。

wrong 的题目 ID 为主键，先 INSERT OR IGNORE 再 count=count+1，所以重复错误不新增相同记录。再次答错把 mastered 恢复为 0。正确重练后仍由用户主动标记掌握。

SQL 查询使用 ? 参数；Cursor 通过 try-with-resources 关闭。BaseActivity 在 onDestroy 关闭自己持有的数据库帮助对象。关键学习数据在用户操作时即时保存，不依赖 onDestroy 必然执行。

## 统计

只要一章所有知识点状态为 2，该章算完成。分母来自 availableChapters，不再写死为四。

累计正确率使用历史答对总题数除以历史总题数，包括错题练习；每章成绩单独取 kind='chapter' 的最近一次记录。没有答题记录时显示暂无数据，避免除以零。最近记录最多显示十二条。

## 页面跳转实验

NavigationActivity 输入学习目标，Bundle 传给 MessageActivity。子页面显示收到的数据，输入回复后通过 setResult 返回。父页面处理成功与取消两种分支。输入为空时给 Toast，不启动无意义操作。

StudyFragment 在同一 Activity 中切换局部提示，不启动独立 Activity。Fragment 在 onCreateView 加载自己的 XML。首次创建才添加默认 Fragment，重建时让系统恢复已有实例，避免重复添加。

## 当前实现边界

本项目数据量小，数据库与 JSON 处理仍在主线程；未做大规模题库性能优化。题目顺序固定，题库不是随机试卷。列表使用课程原生 ListView，未改成 RecyclerView。没有虚构未提供的第六章。完整触摸流程、横竖屏与大字体仍需在设备上验收。

## 2.1 代码与效果实验室的执行流程

LabCatalog 创建十个 LabExample 条目，保存示例名称、学习目标、XML 资源 ID、源码文件路径和绑定类。LabActivity 选择条目后只读取源码，不执行演示。

点击运行时，先用 LayoutInflater.inflate 得到该示例 XML 的根 View，再调用 example.binding.bind(demoView)。DemoButton 等绑定类执行与代码窗口相同的 Java 方法，安装真实事件监听器。运行后的按钮、滑块、列表均为 Android 原生 View。

切换示例时清空原预览并显示未运行提示；重新运行时重新加载 XML，得到新的控件实例与初始状态。展开代码对话框可查看完整源码并复制。页面重建保存所选示例、XML/Java 标签和是否已运行；部分交互控件状态由 Android 自身恢复，不作为永久学习记录。

新增示例时要同时注册元数据，并同步 assets/lab 中显示的源码副本。tests/check_lab.py 会检查两份源码逐字节一致，防止讲解和运行实现逐渐不一致。
